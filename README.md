# build-3d-world

基于地图数据的程序化三维街景生成研究。

## 为什么建立这个仓库

这个项目源于我对 **Rokehan（随处勘景 / どこでもロケハン）** 的学习。最吸引我的，是它能够以真实地图数据为基础，结合高程信息和程序化建模规则，生成包含建筑、植被、道路与地形的三维场景。这为我构建可交互的三维世界环境提供了很好的启发。

为保存这份参考实现并方便后续研究，我将网页公开提供的运行代码整理、留存于此。后续将重点研究**如何从地图数据生成三维街景**，逐步理解和探索地理数据处理、建筑几何生成、植被生成、地形融合与场景渲染之间的完整流程。

## 本地运行

需要 **Python 3.10 或更高版本**，以及支持 WebGL 的现代浏览器。服务仅使用 Python 标准库，无需安装第三方 Python 包，也不需要 Node.js 构建步骤。

```bash
git clone https://github.com/Cooperoh/build-3d-world.git
cd build-3d-world
python server.py --open
```

Windows 也可以双击 `start-local.cmd`。

默认打开北京参考场景。本地服务监听 `127.0.0.1:18764`；端口被占用时尝试到 `18784`，实际端口记录在 `cache/server.json`。不注册开机启动或系统服务。停止服务可关闭运行终端，或执行：

```bash
python server.py --stop
```

首次打开需要联网获取地图与高程数据。仓库中的城市包和搜索索引为空，页面会使用 OpenFreeMap 矢量瓦片生成街区，使用 Terrain Tiles 等数据生成地形，地名搜索回退到 Nominatim。默认启动参数 `overpass=0` 关闭 Overpass 查询，与原站当时的在线取数策略相符。

成功取得的数据缓存在 `cache/http/`，该目录不会提交到 Git。浏览器也保留原程序自身的缓存。已缓存区域可以用 `python server.py --offline --open` 尝试离线打开，缺失的资源仍需先联网获取；`python server.py --online --open` 恢复联网取数。精简版不预置离线场景，使用矢量瓦片与使用城市数据包时，细节可能不同。

## 从哪里开始读代码

原页面通过类似 `// ---- 14_city.js ----` 的注释保留模块边界。可以直接搜索这些标记，或执行：

```bash
python tools/extract_modules.py
```

脚本生成 `work/source-modules/`，只用于阅读，不改变运行代码，也不作为独立工程构建。

| 模块标记 | 研究内容 |
| --- | --- |
| `10_geo.js` | 经纬度到局部坐标的转换、高程读取与地形采样 |
| `12_osm.js`、`13_tiles.js`、`13_vtosm.js` | OSM 要素与矢量瓦片的解析、几何整理 |
| `14_city.js`、`20_build3d.js` | 街区结构组织、建筑高度处理与三维网格生成 |
| `23_facade.js` | 近景建筑立面、窗户、阳台等程序化细节 |
| `24_plants.js` | 树种参数、分枝与树冠生成、季节变化和实例化 |
| `15_far.js`、`18_horizon.js` | 远景与地平线场景的简化表示 |
| `22_lines.js`、`30_view.js`、`31_view.js` | 漫画描边、明暗与网点、光照、相机和显示流程 |
| `80_ui.js` | 场景加载、参数联动和 LOD 调度 |

## 后续研究方向

1. **地图要素到场景结构**：从建筑轮廓、道路、绿地和水域等地理要素，组织可生成的场景数据。
2. **建筑几何与立面生成**：研究轮廓拉伸、高度与层数处理、屋顶构建，以及近景细节的规则化生成。
3. **植被与地形融合**：研究树木分布、程序化树形和地形贴合，使建筑、道路与植物位于一致的空间坐标中。
4. **场景规模与交互性能**：研究 LOD、实例化、瓦片划分和缓存，支持更大范围的浏览与模型导出。

研究中将区分**有地图数据依据的几何结构**与**通过规则推测或补充的视觉细节**。缺少建筑高度时的估算，以及窗户、阳台和树木外观等程序化补充，不应直接视为真实世界的精确测量结果。
